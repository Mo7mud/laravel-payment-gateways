# سجل التجارب على البوابات

> **القاعدة:** أي سلوك للبوابة مش موثّق، أو التوثيق فيه غامض، لازم يتجرب ويتسجل هنا. بعد كده بنحدّث `docs/gateways/*.md` ونغيّر علامته من ❓ لـ 🧪 (E-xx).
> **ممنوع** تحط مفاتيح أو بيانات كروت أو بيانات عملاء حقيقية. الـ payload بيتحط بعد ما نمسح منه: `signature`، و`hashKey`، و`transactionHashKey`، والإيميلات، والتليفونات.

## إزاي تسجّل تجربة
```md
### E-K3 — <العنوان>                         الحالة: ⏳ مخطط | ✅ اتعمل | ⚠️ النتيجة مخالفة للتوثيق
- **التاريخ / البيئة:** 2026-10-25 · Kashier test · إصدار الحزمة <sha>
- **السؤال:** …
- **الخطوات:** 1) … 2) …
- **المتوقع (حسب التوثيق):** …
- **النتيجة الفعلية:** …
- **الدليل:** payload بعد التنضيف / لقطة شاشة / سطر من اللوج (`storage/logs/payments.log`)
- **الاستنتاج:** …
- **اللي اتحدّث:** docs/gateways/kashier.md §2 · R18 · test جديد `tests/...`
```
**مصادر الدليل:** جدول `gateway_payment_webhook_events.payload` (بيتنضف أوتوماتيك من المفاتيح الحساسة)، و`gateway_payments.metadata`، ولوج الحزمة.

## Kashier

### E-K1: دفع كارت ناجح، كامل من الأول للآخر — ⏳
- **السؤال:** شكل الـ webhook الحقيقي و`signatureKeys`، وparams صفحة الرجوع، وأنهي طريقة توقيع للرجوع اشتغلت (الثابتة ولا الـ fallback، R18)، والترتيب: الـ webhook ولا الرجوع يوصل الأول؟
- **الخطوات:** session بـ 10 ج ← كارت `5123450000000008` بتاريخ `06/25` وCVV `100` ← نسجّل الـ payload والـ query
- **المتوقع:** `pay/SUCCESS`، وتوقيع صحيح، والحالة `succeeded`، و`PaymentSucceeded` يطلع مرة واحدة

### E-K2: دفع اترفض — ⏳
- **الخطوات:** تاريخ `05/25` (DECLINED)
- **المتوقع:** webhook بـ `status=FAILURE` ← `PaymentAttemptFailed`، والدفع يفضل مفتوح، والعميل يقدر يحاول تاني لحد `maxFailureAttempts`

### E-K3: محاولة تانية بعد الفشل — ⏳
- **السؤال (من صاحب المشروع):** بعد ما المحاولة تفشل، المحاولة التانية بتبقى على **نفس الـ session**؟ وبيطلع `transactionId` جديد؟ وصفحة الرجوع بتيجي كام مرة؟
- **الخطوات:** E-K2، وبعدها على نفس الصفحة كارت ناجح (`06/25`)
- **المهم:** إن الحزمة تعتبر الدفع ناجح من غير ما تتلخبط من الـ transaction الفاشل (`fillIdentifiers` بيسمح يتغيّر الـ transaction id طول ما الدفع لسه متدفعش)

### E-K4: abandon وبعدين دفع — ⏳
- **السؤال:** الـ session بعد `PATCH /v3/payment/sessions/{id}` ينفع لسه تتدفع؟ (التوثيق مقالش)
- **الخطوات:** نعمل session ← نفتح الصفحة ← abandon من الـ API ← نحاول ندفع من نفس الصفحة اللي مفتوحة ← نعمل reload
- **التأثير:** R16 / ADR-11. لو الدفع نفع، يبقى لازم سياسة الدفع المتأخر تشتغل

### E-K5: Refund كامل وجزئي — ⏳
- **السؤال:** الرد الفوري (SUCCESS ولا PENDING)، وبيجي webhook ولا لأ؟ والـ `event` و`transactionId` بتوعه إيه؟
- **المتوقع:** `refund`/`partial_refund` بـ `status=SUCCESS`، والـ ledger يتطابق مع `refundedAmount`

### E-K6: محفظة — ⏳
- **الخطوات:** Vodafone Cash `01010101010`. وتاني بـ `01001001001`
- **نسجّل:** `method`، والحالات اللي بيمر بيها (PENDING ← SUCCESS؟)، وهل فيه OTP

### E-K7: التكرار والـ retry — ⏳
- **الخطوات:** (أ) نعيد إرسال webhook حقيقي (replay من اللوحة لو متاح) ← نتوقع 409. (ب) نخلّي الـ endpoint يرجّع 503 مؤقتاً ← نسجّل مواعيد الـ retry ونقارنها بالتوثيق (2د، 10د، 30د...)
- **التأثير:** R1

### E-K8: انتهاء الـ session — ⏳
- **الخطوات:** `KASHIER_EXPIRE_MINUTES=5` ← منعملش أي حاجة ← نشوف حالة الـ session بعد كده ← نشغّل `payments:reconcile`
- **المتوقع:** الحالة `expired`، و`PaymentClosed`

## Fawaterk

### E-F1: كروت الـ staging — ⏳
- **السؤال:** الكروت اللي في التوثيق (تاريخها 12/26 و05/26) لسه شغالة؟
- **نسجّل:** شكل الـ webhook الحقيقي لـ paid وfailed (الاتنين `_json`)، وإن `transaction_key == intent_key`

### E-F2: `payment_method_id` + `redirectOption: true` — ⏳
- **السؤال:** الوسيلة بتبقى متختارة بس والعميل يقدر يغيّرها، ولا هي الوحيدة اللي بتظهر؟ والرد فيه `data.url` ولا `payment_data.redirectTo`؟
- **التأثير:** ADR-10 (هل الراكب ممكن يدفع بفوري)

### E-F3: `due_date` و`expires_in` — ⏳
- **الخطوات:** `fawaterk_due_date` = بعد ساعة ← نقارن `expires_in` في الرد، ونحاول ندفع بعد الميعاد
- **التأثير:** R17 / ADR-13

### E-F4: كود فوري — ⏳
- **الخطوات:** hosted ← نختار فوري ← نسجّل الكود اللي ظهر، وwebhook الـ `pending` (هل بيجي؟)، وإزاي نحاكي الدفع على staging (لو مش متاح، نسأل الدعم)
- **المتوقع:** `pending` ← وبعدين `paid` (webhook)، و`PaymentSucceeded`

### E-F5: Failed webhook — ⏳
- **السؤال:** الـ failed بيجي لكل محاولة فاشلة؟ وبيجي JSON مع `failed_json`؟

### E-F6: سياسة الـ retry — ⏳
- **الخطوات:** الـ endpoint يرجّع 503 لـ paid ← نسجّل بيتبعت تاني ولا لأ، وامتى (مش موثقة)

### E-F7: Refund + الموافقة — ⏳
- **الخطوات:** refund جزئي ← نشوفه في الـ refund list (`pending`) ← نوافق عليه (من اللوحة؟) ← webhook الـ refund
- **نسجّل:** قيم `status` (integer) في الـ webhook وفي الـ list، وقد إيه بيتأخر

### E-F8: Cancel webhook — ⏳
- **الخطوات:** كود فوري/أمان يخلص (أو `due_date` قصير) ← نشوف بيجي `cancel` بـ `EXPIRED`؟
- **المتوقع:** `PaymentAttemptFailed`، وبعدين `expired` من الـ reconcile

### E-F9: محفظة من الصفحة الـ hosted — ⏳
- **السؤال:** المحافظ (Vodafone Cash وغيره) بتظهر في الـ hosted ولا Meeza بس؟ وبتحتاج OTP؟
